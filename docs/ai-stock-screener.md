# AI 选股

入口为侧栏「AI选股」，地址 `#/screener`，详情 `#/screener/:id`。本次实际操作 [88AI AI选股页](https://88aitou.com/search) 的示例、提交、候选结果和历史入口，并核对其公开 API 文档，替换此前仅展示通用聊天的实现。详见 [交互核实记录](ai-stock-screener-reference-audit.md)。

## 实际流程

输入自然语言条件，或选择六个可编辑示例；Enter 开始、Shift+Enter 换行。默认使用当前 DSH 默认模型，也可为新查询选择模型。创建独立 DSH Session 后，模型在会话工作区写入 `screening-plan.json`，宿主在回合完成时读取并严格校验，不能只贴一段聊天或候选名单冒充执行结果。

计划保留原始问题、解释、精确查询、阈值假设和接口无法验证的条件。白名单查询复用财务扫描契约，固定第一页；行业通过本地已核实分类做精确匹配，不拿“名称包含银行”冒充银行行业，也不把题材概念当行业。

明确且无假设/缺口的财务计划自动读取本地指标；有默认阈值、指定财报期、连续季度改善、订单、放量突破等无法直接验证的条件时停在「等待确认」。用户可以确认仅执行可用条件，页面仍保留未验证项，不能把候选说成已满足原问题全部条件。没有可执行条件不扫描全市场，不返回随意推荐；需重新补充问题。

模型不负责生成股票价格、评分或逐股理由。候选由宿主使用本地证券名录、报价和财报事实筛选与排序；AI选股不调用88AI。财务缺口交给已有持久同步队列，字段、统计期、来源和缺失覆盖随结果冻结。技术查询遍历本地范围并保留全部命中计数，最多保留100只候选、展示前20只；财务查询返回第一页100条并展示前20只，不将展示样本当作全市场。

解析中自动显示原生 DSH 对话与工具审批。模型工具不可用、没有写文件、JSON无效或问题不匹配时明确失败；不会把聊天文本解析成股票事实。完成后的对话可展开查看或继续研究，但追问不改写已经冻结的候选；调整条件在上方重新发起查询。

## 候选、口径与动作

卡片展示名称、代码、行业、价格、涨跌幅、PE、ROE、毛利率、市值与实际筛选条件对应值。非空字段覆盖只统计当前展示样本，不代表完整性审计。缺失值为破折号，真实源零值保留；来源快照日不是公司财报期或实时报价。具体财报口径、股息和资金字段仍需复核。

「查看当前K线与详情」打开已有个股页，明确是当前研究视图；不会把当前行情混入已保存的候选。「加入当前自选」仅在点击时调用现有自选 RPC，可选择分组；不自动写入账户或交易系统。

## 持久化、恢复与兼容

复用 `expert_chats` 的 `master_id=ai-stock-screener` 记录元数据和 DSH Session，不另存聊天消息。业务状态和冻结结果使用已有 `app_settings` 的 `ai-screener.run.<id>`，位于宿主数据库，不把模型工作区的同名“结果文件”当作行情来源。状态包括解析、待确认、扫描、就绪、失败。查询源的历史与缓存继续复用 `MarketScanService`、`MarketHistoryStore`、`ProviderCache` 和统一熔断，不新增行情源或财务快照表。

成功结果按这次查询冻结；查看历史不重新调用模型或行情。启动恢复时，仍运行的 DSH Session 继续等待；已保存计划或已开始扫描的任务可从计划恢复，不能恢复的中断任务明确失败。重复完成事件合并，已经完成的结果不因后续聊天事件重新扫描。关闭宿主后不向已关闭数据库写入状态。

失败记录支持手动重试：没有有效可执行计划时显示「重试解析」，沿用原始问题及记录中的模型（未指定模型时使用当前 DSH 默认模型）新建查询，保留失败历史和输入框草稿；已有有效计划时显示「重试候选查询」，继续执行已校验条件，不重新调用模型。重试期间禁止重复提交，创建失败可再次重试。

旧版选股对话没有结构化业务记录时保留原生对话入口，不虚构候选。删除需要确认；DSH 正在运行或扫描任务尚未完成时拒绝删除，删除后移除本地业务状态和工作区并归档 DSH Session。不保证物理删除 DSH 自身日志。普通行情缓存清理不删查询历史。

## 动态技术公式与全市场后台扫描

AI可以在原计划中增加 `technical` 对象：`match` 为 `all` 或 `any`，`adjust` 为 `qfq` 或 `none`，`rules` 是1—20条受控规则。已实现 `ma-spread`（指定均线集合的极差比例及持续天数）、`ma-cross`（指定两条均线在窗口内实际交叉）、`ma-turn`（斜率变号）、`price-ma`（收盘与均线比较）、`limit-up`（指定窗口内的核实收盘涨停次数）。参数由AI动态生成；用户未说明的阈值、周期或定义必须列入 assumptions，页面展示公式后由用户确认。没有 eval、脚本执行或任意URL能力。其它指标和嵌套逻辑仍须明确 unsupported，不能偷偷替换。

技术公式整体与财务条件为 AND；技术内部可 all/any。技术条件本身已构成有效筛选，不要求凭空加财务阈值。宿主通过同一 `MarketScanService` 枚举源覆盖的当前存续A股全部分页；有财务/行业条件时枚举该条件的全部分页。分页快照日期、总数和代码唯一性均校验；变动或缺失则失败，不能拿前100只冒充全市场。目录并非完整退市历史，扫描不提供历史无偏回测。

截止日先按北京时间收盘缓冲确定上界，再以公开指数日线确定实际已收盘市场交易日。全部股票按统一基准日计算。关闭值见、浏览器或切换页面不取消宿主队列；单宿主按任务顺序、每批最多3只执行，每批持久检查点，原始冻结目录只保存一次。关闭宿主会中止未完成请求，重启从最后已保存批次续传。重试失败任务复用冻结计划及检查点；目录分页发生变动时须新建查询。已完成历史不重新扫描，不改其它查询结果。

均线按请求复权日线自行计算，不信任模糊预设信号。上穿为前日短均线≤长均线、当日短均线>长均线；拐头为前日斜率≤0且最新>0（下行反向）。均线粘连为窗口每一天的 `(max(MA)/min(MA)-1)*100≤maxPercent`。缺少所需历史、日线警告、停牌零量或近期日期未对齐均不强行命中。技术历史使用当前可核实的复权序列，不冒充当时已知数据。

涨停条件不按统一10%猜测。只有在日期明确且已收盘的历史涨停池中出现，并能以同日不复权日线核实收盘等于最高价且有成交，才确认一次收盘涨停；股票当日板块/ST/上市初期规则由历史池事实承载。池可能排除ST/新股，缺少或未入池不推断“没有涨停”，证据不足标为未核实。未核实数量与最多20条原因样例在进度中可见；未核实股票不混入命中列表。

复用 `app_settings` 的选股任务存储，增加同任务技术检查点与冻结目录键；不新增表。进度单独返回总数、已检查、命中、未核实，避免每次轮询传全市场目录。冻结结果最多保留100只、页面展示前20只，并明确总命中数；每只包含计算公式、是否满足及数值/日期证据。财务字段使用目录快照日，技术基准日独立展示，二者可能不同，不把当前财务值冒充过去数据。

技术接口仅使用公开免登录数据；`/api/assets/scan` 的预设信号不作为本组合筛选执行器，不调用88AI的AI推理或登录接口。使用生产插件时重新生成 `pnpm run pack:plugin` 的安装包后更新并重启安装所在Profile，旧失败记录通过“重试解析”创建使用新指令的任务。

### 日线复用与时间语义优化（2026-11-02）

技术原始输入与查询历史分开保存。`TechnicalHistoryStore` 使用同一业务 SQLite：`stock_daily_raw` 按代码、日期积累不复权日线及来源和获取时间；`stock_daily_basis` 保存当前完整前复权窗口及其基准日。相同基准日的新查询及宿主重启可复用输入，删除单次查询不删除这些输入。前复权基准日改变时整段替换，禁止追加拼接两个复权基准；较旧查询不能覆盖更新的前复权基准。不复权回补保留其它日期，较早获取的响应不能覆盖较新的修订。

日线必须有合法顺序、价格和日期，且最后日期达到扫描基准日才写入完成窗口。空响应、报错和来源滞后不会成为已补齐记录。暂停续跑时已处理但未核实的股票会重新核验，成功的本地输入继续复用；历史涨停池失败的空值会重新请求。旧检查点只有20条错误样例、无法恢复完整未核实名单时，从冻结目录重新核验，避免永久跳过未知股票。完成结果依然冻结，不因后台数据更新自动改写。

规则新增可选 `offset`（0—60个市场交易日），用于明确“此前某个窗口”和“近期交叉”等日期关系；`ma-slope` 表示指定天数持续上行/下行，与 `ma-turn` 的当天斜率反转分开。AI必须显式提出并确认不明确的参数，不得自动放宽条件。固定偏移不等于任意事件顺序搜索，超出算子能力仍须列为未支持。均线计算校验整个所需交易日窗口，不能把缺失日期压缩后计算为连续均线。

`StockDataSync` 是独立宿主后台任务：启动恢复未完成游标，每日北京时间20:00后检查增量日期，启动时补跑遗漏；手动触发60秒冷却，自动失败重试至少间隔6小时，二者解耦。每批最多2只，分别核验并存储不复权、前复权窗口；暂停保留有效输入，宿主关闭后不再写库，重启继续未完成批次。设置与诊断新增“选股数据管理”，显示基准日、已检查、窗口就绪、待补、最近全量成功日期和最多20条原因，可同步、重试和暂停。原“立即同步主数据”改为“同步证券名录”，明确不含日线。

技术日线优先使用腾讯公开接口，按明确的 `day` / `qfqday` 字段核对复权身份；腾讯失败或末日滞后时尝试88AI，均失败则保留缺口。原始记录保留实际来源ID与获取时间，不把腾讯数据标记为88AI。指数日线交易日历以88AI优先、腾讯上证指数日线备源，不能把周一至周五直接当成交易日历。已实测002594、002415的两种口径各400根日线均覆盖2026-10-30，并在隔离SQLite中逐字段核对持久复读；这不是全市场或真实模型生成验证。

选股结果增加“数据覆盖与逐条件统计”：全部规则可核实数、按公式命中数，以及每条规则独立的满足、不满足、未核实计数。各行不是按顺序扣减；`any` 可在某条件满足时命中，即使其它条件未知。续跑重试先扣除旧计数再加入新计数。失败样例去重，并区分日线末日滞后与历史窗口不足，不用重复的笼统错误填满页面。

`TechnicalData` 统一管理扫描与同步的本地读取和公开源补取：同代码、复权方式及基准日的请求合并，宿主内最多2个日线下载并行。一个观察者取消不会取消其它消费者的共享请求；宿主停止后排队任务拒绝，迟到响应不写库。raw已有历史且近端缺口不超过14个自然日时取40根重叠窗口修订与追加，初次或较久缺口取400根；qfq固定400根完整基准刷新。两只实测股票的40根raw更新后，原400根历史逐字段保持一致。选股页显示最近全量成功日期及同步状态，可进入设置的数据管理；来源和窗口日期详情可折叠，不把窗口日期范围当作连续完整性证明。

历史涨停证据使用轻量成员接口，不再依赖连续板解释、晋级率、炸板率或昨日表现。复用同花顺日期/分页/封板时间校验，失败尝试东方财富收盘池；按日期持久保存于 `stock_daily_limit_pool`，标记 `source-pool-positive-only`，失败不存为“空池成功”，刷新失败保留已有正向事实。每日后台任务同时补最近20个指数交易日的池；新查询复用共享证据，冻结结果不随之重算。2026-11-01实际取回并持久化2026-09-28至10-30的20/20个交易日成员。未入池不证明没有涨停；当有成交且raw收盘低于当日最高价时，可确认该日不是收盘封板，其余不明日期仍未知。完整ST、上市初期、北交所及停牌历史状态未取得时不套固定比例、不伪造规则。

宿主新一轮同步先核对本地覆盖，复用24小时内有效证券名录，过期才更新，不依赖设置页面打开。名录失败且已有本地范围时继续处理已知股票、显式提示范围沿用，且不推进“全量成功”日期；没有名录则明确失败。名录请求收到宿主停止信号后不写库。自动重试从失败结束时起算六小时，长任务不能因开始时间已久而立即重试。每批2只之间只让出事件循环，本地复用不等待，暂停在最后一批也不会被完成状态覆盖。失败股票重新命中时按原冻结目录的排序插入，最多保留排序后的100只及其证据，避免重试改变候选排序。

日线、交易日历、财报/分红与涨停池的实际补取共享同源请求起始间隔500毫秒（东方财富各域名归为同源），不同来源独立排队，缓存命中不进入请求队列。选股补缺的报价也通过同一限速传输实例，仅在实际HTTP请求时等待；今日市场报价继续使用原调用链。选股日线、指数交易日、报价、财报和分红使用独立熔断键；同能力连续3次服务/格式失败后冷却5分钟。有效响应中的单股空日线、末日滞后、缺少所需复权序列或无财报属于覆盖缺口，不推进就绪状态、不参与全源熔断；无效结构、错股和价格异常仍算失败。取消请求不计失败；覆盖缺口或其它能力成功不能清除既有服务失败。财报和分红在缓存内执行各自熔断，失败继续沿用各股已有成功缓存；熔断状态进入设置诊断。固定限速不能保证避免服务端封禁，仍保留失败、冷却与持久队列重试。

### BaoStock优先的数据准备

### 本地选股与88AI解耦（2026-11-02）

AI选股使用 `LocalScreening`，不再注入普通市场扫描的88AI服务。完整候选范围来自 `security_master`；本地报价/财报事实保存在 `stock-data.metrics.<code>`，按字段保留来源、来源日期、报告期和原获取时间。空值和失败不覆盖已有事实，旧事实保留但不自动当作当前输入。缺少筛选字段的范围单列未核实，不视为条件不满足；排序字段缺失置后并提示，同值按代码确定顺序。分页输入版本变化时拒绝混合扫描。

设置中的持久后台队列同时准备不复权/前复权日线、报价和财报。财务查询缺少输入时等待共享准备任务，确认请求立即返回后台状态；页面离开不取消。日线与指标失败独立显示，财务有效响应不表示所有字段齐全。交易日历持久保存在 `stock-data.calendar`。技术数据使用腾讯优先、东方财富备源，不调用88AI；有本地有效窗口时直接复用。历史涨停仍用同花顺/东方财富的正向事实，缺失不伪造涨停规则。

### 同基准日的增量待办

新一轮任务先使用可复用的本地日历确定基准日，通过已验证窗口的持久覆盖索引统计两种日线均齐全的股票，并立即计入进度。仅缺少日线的代码进入日线待办；原始日线近端增量与前复权整窗规则保持不变。日线就绪统计不等于所有技术条件可核实。

报价/财报待办独立于日线：支持的字段（不包括未支持的5日净流）必须齐全、满足基准日与来源时间要求，且各字段获取时间未超过6小时，才作为本地复用。有效响应但缺字段不算可复用完整数据。逐股完成记录、失败、复用数量与准备阶段随现有stock-data.work持久化，兼容旧检查点；仅有旧计数而无价格窗口或财务事实时不会凭计数宣告数据齐全。重启恢复保留已记录尝试，新一轮重试只处理剩余缺口；新基准日重新检查两类覆盖。日线源熔断时仍处理独立的财务待办，最后保留失败状态供重试。

取消固定的每批500毫秒等待，保留事件循环让出与2只并发上限。实际日线、报价、财报、涨停池仍经过同源HTTP限速，BaoStock仍共用匿名会话串行限速；清理行情缓存不删除业务输入。页面显示本轮本地复用数量，已检查/就绪包含这些本地核对结果，未检查仅反映本轮待办。

主源事实超过6小时且本轮无法获取新值时，允许同日新鲜备源事实接管，保留备源的真实获取时间与来源，避免旧主源永久占位造成反复补取；历史原始日线的逐日主源优先规则不变。损坏的本地财务事实不计入复用，只有取得并验证新的有效字段后才替换，失败仍保留原存储。
