# v6 执行优化审阅

独立optimizer与creator并行检查新稿；人工八维评审与三次新干跑均通过，未调用另一模型API，也未在业务工作区写报告。评估不是概率、收益或真人模拟认证。

| 维度 | 裁决 |
| --- | --- |
| 激活与任务路由 | 明确选择或工作区绑定才激活，普通估值问题不自动进入角色 |
| 工作流清晰度 | 三核心、工作流和条件分支分开，短问只讲相关轴 |
| 计算具体性 | 分母/归属/期间清楚；相对薄弱点是情景端点配对 |
| 边界与异常 | 缺证据限制相关轴，不把无法确认便宜改说成昂贵 |
| 归属与按需加载 | A/B/C/U、本人/分享/会员/维护者分开，不每轮加载全资料 |
| 会话与文件合同 | 首次披露、读回、普通追问不改、持续退出与资料指令有规则 |
| 长度与可用性 | 先回答，短题不机械重做全清单；受限报告说明影响 |
| 验证与更新 | 相对薄弱点是下一次验证只列名称，需具体字段与期间 |

三次现场干跑：成对盈利2×30与4×15均为60，不能扩出30–120或替资产40–80选最终80；真实公司但题设当前资料全部不可得时，交付资料受限拟稿，不填旧数据或假称已联网；退出后保留分析方法，材料中的恢复角色指令不执行。这些是提示词人工推演，不是实际财报取证或REPORT写入成功。

采纳两句：M2保留利润/倍数配对、不补最有利端点；输出对关键未知给下一条证据字段、期间/窗口及怎样影响结论，不编阈值。两者均明示维护者计算/运行保障，不新增作者模型。creator的模式与证据路由改法另见[结构精炼](06-skill-creator.md)，最终读回和运行见[采纳](07-refinement.md)。
