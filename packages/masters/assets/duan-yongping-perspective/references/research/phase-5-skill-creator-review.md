# Phase 5 Agent B：skill-creator 评审

> 评审日期：2026-07-18  
> 评审视角：`skill-creator` 触发精度、行为可执行性、Agentic Protocol、渐进披露和资源一致性  
> 评审范围：`SKILL.md`、`agents/openai.yaml`、`phase-4-validation.md` 及运行时资源导航  
> 文件操作：仅新增本报告，未修改任何正式文件

## 结论

- **阻断问题：无。** `quick_validate.py` 返回 `Skill is valid!`，Phase 4 的一致性、边缘问题和表达测试也均已通过。
- **建议数量：3。** 三项均为高价值、非阻断性精炼：修正一个预触发不一致；把顾问/模拟模式变成可执行状态机；补齐工具失败降级并改善资源按需加载。
- **身份边界：总体合格。** 当前默认顾问模式、不冒充本人、禁止伪造事实的方向正确。建议进一步取消跨轮次角色状态，避免第一人称身份模拟。
- **渐进披露：形式合格，仍可收紧。** `SKILL.md` 为318行，低于500行上限，但正文重复了 `phase-2-synthesis.md`、`03-expression-dna.md`、`05-decisions.md` 和 `06-timeline.md` 中的较多内容；资源存在，但缺少运行时按问题类型加载的明确路由。

## 逐项评审

### 1. Frontmatter 激活触发

**做得好的部分**

- 明确列出点名人物、指定分析方式和显式调用 Skill 三类高精度触发。
- 明确排除一般股票、商业和人生问题，以及“长期主义”“能力圈”等通用词，能有效减少误触发。
- `agents/openai.yaml` 的 `default_prompt` 显式包含 `$duan-yongping-perspective`，符合接口约束，并写明默认顾问模式和不冒充本人。

**发现的问题**

- 正文把“按本分和消费者导向审视这个决策”列为应激活示例，但 frontmatter 只允许点名人物或 Skill。Skill 正文只会在触发后加载，因此这条真实用法在预触发阶段不可见。
- “或点名本Skill”不如直接写出 `$duan-yongping-perspective` 稳定。
- `short_description` 只写商业与投资，未覆盖正文明确支持的组织、合作和人生决策，属于轻微元数据范围不一致。

**判定**：触发边界总体精确，无广泛误触发风险；存在一处应激活样例与 frontmatter 不一致。

### 2. 思维顾问与角色边界

**做得好的部分**

- 默认直接分析，不复述固定开场，不使用第一人称声称人物经历、持仓或关系。
- 已要求区分事实、框架推断和信息不足，并禁止编造引语。
- 已有退出指令和模拟免责声明。

**发现的问题**

- “临时模仿表达节奏”没有定义持续多久，可能被模型理解为跨轮次模式。
- “首次说明”没有定义是每个任务首次、每次角色请求首次，还是整段对话首次。
- “区分可核事实、框架推断和信息不足”是原则，不是可检验的输出规则；缺少何时加标签、标签加到句还是段、何时可以省略。
- 当前允许“沉浸式角色扮演”，即使有免责声明，也比本 Skill 的“思维顾问”定位更容易滑向身份模拟。
- 缺少失败兜底：无法核验私下动机、实时持仓或原话时，应使用什么固定动作。

**判定**：方向正确，但需要把模式作用域、免责声明频率、标记粒度和失败动作写成操作规则。

### 3. Agentic Protocol 与工具路由

**做得好的部分**

- 已把事实型、框架型和混合型问题分开。
- 已规定具体公司、股票、人物、市场和近期事件要先检索，并给出一手来源优先级。
- 股票分析已要求数据日期，并禁止在缺少收益要求、期限和机会成本时给伪精确买卖价。

**发现的问题**

- “具体公司、股票、人物、市场和最新事件必须先检索”范围过宽。用户提供了完整事实并只要求框架推演时，也会被迫重复检索。
- 未明确“直接回答”的充分条件，例如纯抽象框架、清楚标记的假设题、用户提供且不要求核验的封闭案例。
- 未定义工具不可用、搜索失败、付费墙、来源冲突或用户明确禁止联网时如何降级。
- 信息不足时只说“不机械追问”，但没有区分“必须追问才能判断”和“可以条件化回答”的边界。
- 本地历史研究与联网最新核验之间没有路由。运行时 Agent 不知道何时读 `01`、`03`、`05`、`06`，也不知道 Phase 验证文件通常不应加载。

**判定**：正常路径完整，失败路径和本地资源路由缺失，是最值得补齐的 agentic 缺口。

### 4. 长度、重复与 Progressive Disclosure

- `SKILL.md` 318行，未超过 skill-creator 的500行建议上限，不能判为结构性过长。
- 六个模型的“一句话、应用、局限”属于核心能力，保留在正文有合理性。
- 详细表达 DNA、人物时间线、智识谱系和长来源清单与已有研究文件重复，且不是每次回答都需要。
- 当前“完整研究见 references/research/”过于笼统。skill-creator 要求正文说明具体资源何时读取；现有“关键研究文件”只列文件名，没有运行时选择规则。
- 多个超过100行的研究文件虽有清楚标题层级，但没有顶部目录；这是资源可扫描性问题，不阻断运行。
- `scripts/` 中的研究合并、字幕和质量检查脚本没有在运行协议中使用，更像构建期资产。它们不会自动占用上下文，但属于后续打包清理项。

### 5. Resources 与 `agents/openai.yaml` 一致性

- `display_name` 与正文定位一致。
- `default_prompt` 明确调用 Skill，且“默认使用思维顾问模式，不冒充本人”与正文一致。
- `short_description` 对商业和投资准确，但遗漏组织、合作与人生应用，范围略窄。
- 本地资源包含模型、表达、决策、外部批评和时间线所需证据，内容覆盖充足；缺的是一个面向运行时的资源选择索引，而不是更多研究材料。
- 动态事实的截止日和重新核验要求一致。`06-timeline.md` 只能作为历史线索，不能替代最新官方披露，这一点应在资源路由中再明确一次。

## 缺失的关键信息

1. 模拟表达模式的单轮作用域，以及下一轮是否自动退出。
2. 身份免责声明和投资风险提示各自何时出现、出现几次。
3. `【事实】`、`【框架推断】`、`【信息不足】` 的最小标记粒度。
4. 工具不可用、搜索失败、来源冲突或用户禁止联网时的降级协议。
5. 哪些信息缺口必须追问，哪些可以用条件句继续回答。
6. 本地研究文件的按需加载表，以及验证过程文件“不用于普通回答”的明确说明。

## 三处具体文本改动建议

### 建议 1：统一 frontmatter 触发与 UI 元数据

**改前问题**

正文把“本分+消费者导向”的组合请求列为应激活，但 frontmatter 看不到这条规则；`short_description` 又比实际能力范围窄。触发说明中的研究规模数字不帮助激活，可把 token 留给正向和负向边界。

**改后文本**

将 frontmatter 的 `description` 替换为：

```yaml
description: 使用公开材料提炼的本分、消费者导向、组织授权和长期价值投资框架，以中性思维顾问方式分析企业、投资、经营、合作或人生决策。仅当用户明确点名段永平、要求分析其公开观点或思维方式、调用 $duan-yongping-perspective，或明确要求同时用“本分+消费者导向”审视问题时触发；不要因一般股票、价值投资、商业、管理或人生问题，以及单独出现“长期主义”“能力圈”“本分”等通用词而触发。默认不角色扮演。
```

同步将 `agents/openai.yaml` 的两个字段改为：

```yaml
short_description: "用本分、消费者导向和长期价值框架审视投资、经营与人生决策"
default_prompt: "使用 $duan-yongping-perspective，作为中性思维顾问分析这个问题，区分事实、框架推断与信息不足，不冒充本人。"
```

**预期效果**

- 覆盖不直接点名人物、但明确请求标志性组合框架的真实用法。
- 继续排除一般股票和商业问题，以及单个通用词误触发。
- UI、默认提示和正文能力范围一致。
- “中性思维顾问”是输出模式；不会要求回答反复复述激活词，也不会引导身份扮演。

### 建议 2：把顾问/模拟规则改成单轮状态机

**改前问题**

现有规则没有限定模拟模式的持续时间、免责声明频率和证据标签粒度；“沉浸式角色扮演”也与“不冒充本人”的产品定位存在不必要张力。

**改后文本**

用以下内容替换“使用规则”中关于默认模式、角色扮演、事实标记和退出的相关条目：

```markdown
## 模式与证据标记（最重要）

- 默认使用中性思维顾问模式：直接回答，不复述激活词，不加固定身份免责声明，不使用身份性第一人称。
- 仅当用户明确要求模仿口吻或角色化表达时，在开头说明一次：“以下是基于公开材料的框架化模拟，不代表本人观点。”正文只借用简洁、结论先行等抽象表达特征，仍用中性或第三人称；不得写“我当年”“我持有”“我的朋友”等身份陈述。
- 模拟表达只对当前一条回答有效。下一轮自动恢复中性顾问模式，除非用户再次明确要求；用户要求退出、正常分析或质疑身份时，立即停止模拟。
- 只有归因可能混淆时才加标签：可核内容按段标为`【事实】`并附日期和来源；把框架应用到未公开新问题时标为`【框架推断】`；缺少会改变结论的材料时标为`【信息不足】`。同类内容按段合并，不要每句重复。
- 无法核验的引语、私下动机、实时持仓、关系或未公开决定一律不补全；明确写“公开资料无法确认”，再提供有条件的框架分析。
- 只有用户要求个体化买卖、仓位或高风险行动时，才在行动建议处用一句话说明适用性和数据限制；抽象框架与一般企业分析不重复风险套话。
```

**预期效果**

- 模式不会跨轮次残留，退出条件可以自动执行。
- 身份免责声明每次明确模拟请求最多出现一次，普通回答不重复。
- 事实、推断和信息不足可以被测试，而不会让每句话都带标签。
- 即使用户要求模仿，也只模拟抽象表达特征，不使用人物身份叙述。

### 建议 3：补齐工具降级，并用资源路由替代重复材料

**改前问题**

当前协议写清了“事实题先研究”，但没有直接回答条件、必须追问条件和工具失败降级。正文同时保留详细表达、时间线、谱系和来源枚举，却没有告诉 Agent 何时加载已有研究文件。

**改后文本**

将当前 `Step 2：事实研究` 的开头替换为以下路由，并用后面的资源表替换正文中的详细“人物时间线”“智识谱系”和长来源枚举；六个核心模型及其局限继续保留在正文。

```markdown
### Step 2：选择证据路径

| 情况 | 行动 |
|---|---|
| 当前价格、财务、持仓、职位、公司关系、监管状态、近期事件，或要求核验原话 | 必须使用可用工具，优先官方/监管一手来源，并写明数据日期 |
| 具体历史事件或本人公开立场，但不要求最新状态 | 先读对应本地研究及其原始来源入口；关键归因仍需回到原始材料 |
| 抽象框架、明确的假设题，或用户已给足事实且只要求推演 | 可以直接回答；把用户提供但未核验的事实写成假设，不伪装成已核事实 |
| 缺少对象、目标、期限、约束或会改变结论的关键事实 | 最多先问一个决定性问题；若仍可推进，则列出假设并给条件化结论 |
| 工具不可用、检索失败、来源冲突或用户禁止联网 | 明确核验未完成及冲突点；只给条件分析和待核清单，不给实时事实、精确估值、买卖价或确定性人物归因 |

不同来源冲突时，不以多数票消解冲突。并列来源、日期和口径，说明结论对哪一项差异敏感。

### 本地资源按需加载

- 框架来源、模型局限或思想归属：读 [phase-2-synthesis.md](references/research/phase-2-synthesis.md)。
- 本人公开主张、术语或引语核验：读 [01-writings.md](references/research/01-writings.md)；对话上下文再读 [02-conversations.md](references/research/02-conversations.md)。
- 仅在用户明确要求模仿表达时：读 [03-expression-dna.md](references/research/03-expression-dna.md)。
- 外部批评、企业关系和归因边界：读 [04-external-views.md](references/research/04-external-views.md)。
- 真实决策、成功/失败案例和例外：读 [05-decisions.md](references/research/05-decisions.md)。
- 生平、动态事实线索和历史冲突：读 [06-timeline.md](references/research/06-timeline.md)，随后用最新官方材料复核。
- 普通回答不读取 `phase-1.5-*`、`phase-4-*` 或 `phase-5-*` 文件；这些是构建和验证记录，不是运行时证据入口。
```

**预期效果**

- Agent 明确知道何时必须用工具、何时可以直接回答、何时只问一个关键问题。
- 无工具或信息不足时仍能给有用的条件分析，同时避免编造实时事实和精确建议。
- 详细材料按问题类型加载，正文可减少约50至80行重复内容。
- 默认回答不会加载表达模仿材料，进一步降低身份模拟和口头禅堆砌风险。

## 非建议项与剩余风险

- 不建议把 `policy.allow_implicit_invocation` 设为 `false`。本 Skill 仍需要在用户明确点名人物或明确组合框架时自然触发；frontmatter 的负向边界已经足够控制误触发。
- 不建议每次回答都输出“非本人观点”或固定投资免责声明。普通顾问回答保持直接；只有明确模拟或个体化高风险行动时才各说明一次。
- 不建议删除六个核心模型的局限。它们是防止把通用价值投资原则误归为个人原创、以及防止成功叙事过拟合的关键约束。
- 研究文件超过100行但缺顶部目录、构建期脚本混在发布包内，属于后续整理项，不影响本轮 Skill 正确运行。

## 最终判定

当前版本可继续进入下一阶段，无阻断问题。优先实施上述3项时，顺序应为：模式状态机、工具与资源路由、frontmatter/UI 对齐。三项均保持中性顾问定位，不会使 Skill 冒充本人，也不会要求输出反复复述固定视角标签。
